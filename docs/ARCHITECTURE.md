# Architecture and boundaries

The coordinator has no server or telemetry. `config.py` validates YAML and conservative URL identities. `scope.py` applies exact/wildcard host policy, port/scheme restrictions, case-sensitive path restrictions and exclusions. Lab mode permits **only loopback** addresses, not arbitrary internal networks. DNS resolution checks every A/AAAA result; aiohttp connects to those returned addresses with cache disabled and connections closed after each request. Literal addresses receive the same network checks. Native HTTP bypasses environment proxies so a target connection cannot be redirected through an unchecked proxy. Redirects are recorded and queued individually, never followed automatically. Public target scanning therefore requires native DNS/egress; a proxy-only cloud may be unsuitable for real scans.

`engine.py` owns all target HTTP attempts, including retries, crawls, source maps, missing-path baselines and the exposure profile. Sequential dispatch makes global and per-host rate ceilings measurable. GET is the only target request method. Forms are recorded without submission, explicit non-GET JavaScript routes are not fetched, and known non-crawl action paths/queries are denied. An application with side-effectful GET routes still requires the analyst to exclude those paths. No browser is launched. A/AAAA resolution operations and bounded CNAME/wildcard DNS operations have a separate budget; system resolver wire-level retry/query counts are not measurable. Passive tool provider traffic has a separate time/result/output limit and rate flags; its exact request counts remain unknown. Only the reviewed provider allowlist is selectable.

`storage.py` uses atomic directory creation, atomic manifests and exclusive lock creation. New runs never replace existing files, directories or symlinks. The manifest records original target, normalized target, effective configuration hash, schema and run ID. Windows-reserved names and long hostname labels are mapped safely. Use a reasonably short output root on Windows; arbitrary long filesystem paths are subject to the OS's long-path policy. SQLite migrations 0→1 and additive 1→2 are explicit transactions; unknown versions are refused. The `runs`, `hosts`, `dns`, `origins`, `urls`, `parameters`, `artifacts`, `relationships`, `observations`, `findings`, `analyst_actions`, `stages` and `jobs` tables preserve identity separately from observations. Meta records carry counters, local analysis caches and checkpoints.

A request reservation is persisted before sending. Each completed job is durable. A graceful Ctrl+C/SIGTERM finalizes the partial checkpoint and report and releases the run lock. A hard kill can leave a stale lock and a running job; use `--break-lock` after confirming no process is alive. Resume resets only running jobs to queued; completed jobs are not reissued. A hard kill between an HTTP response and durable completion can repeat that idempotent GET; this is at-least-once dispatch, not exactly-once network delivery. Consumed requests and elapsed scanning time do not reset on resume. Raising a cap requires a new run. Config and executable identity changes require a new run. Failed jobs are retained; they are not silently retried indefinitely. Fresh runs revalidate liveness.

Content files have SHA-256 names, never target-supplied paths. Identical JavaScript is parsed once; source relationships are retained per page. Tree-sitter extracts syntax-based static strings, methods and code keys; dynamic expressions remain unresolved. This is static analysis, not complete runtime JavaScript coverage. Source maps v3 with embedded `sourcesContent` are bounded; source filenames are never written or fetched. Indexed maps, inline data-URI maps and external source content are not fetched. Gitleaks and jsluice run locally on artifacts only. Their raw stdout/stderr is redacted. Captured response bodies remain restricted raw evidence. Redaction is pattern-based and cannot promise to remove every sensitive value; review exports before sharing.

The scan disk cap includes current database, raw captures and artifact files and reserves a conservative metadata-based allowance for final reports. SQLite WAL/filesystem allocation and finalization overhead are approximate bytes, not a hard OS disk quota. Very small caps can be exceeded by the minimum database/checkpoint/report required for a useful interrupted run. Per-response compressed input and decompressed output are bounded; unsupported encodings fail explicitly. HTTP content similarity is a hint; restricted and server-error responses remain live responses. Observations are not deleted by display or scheduling filters.

Finding priority is a documented investigation ordering: recognized secret syntax 80, exposed environment signature 85, Git HEAD 75, dangling in-scope CNAME/NXDOMAIN 60, directory listing 55, debug surfaces 50, API documentation/routes 45, published source maps 25; restricted sensitive routes gain 10 and synthetic secrets score 5. Each finding records reasons, detector confidence, unassessed severity and candidate status. Multiple source relationships remain visible rather than being turned into an exploit probability. Only `reconmap validate` with an analyst note can mark a finding manually confirmed.

Reports use local assets, escaped HTML, inert escaped JSON and text-only rendering of hostile records. They do not load target resources. Hash-only artifact links are downloads of **restricted raw evidence**, not sanitized web pages. CSV cells neutralize formula prefixes. Baselines are opened read-only. Diff absence is always “not observed this time”; it is never automatically “confirmed unavailable.” Scope/settings differences and incomplete coverage are reported.


## V2 orchestration and compatibility

`tool_registry.py` owns permanent IDs, pins, capabilities, risks, dependencies and policy reasons. `selectors.py` resolves CLI/YAML profiles and selections; no external dependency scanner is implicitly selected. `commands_v2.py` keeps plan/tool/rerun commands out of the existing entry point. `orchestrator.py` validates a topological dependency graph: discovery → passive/Wayback → validated DNS → native web/captured-artifact waves → standalone offline analysis → observed-IP ASN metadata → normalization. Local inputs precede web work. The web phase alternates completed native crawl batches with offline tools, then checks newly inferred GET candidates through the same scheduler; it never overlaps target-active scanners. A later offline phase catches local-only executions and cached completion. `integrations.py` reuses the V1 argument arrays, bounded subprocess handling and parsers. Persisted tool identities, statuses, invocations, normalized observation/finding counts and per-invocation captures explain coverage independently of workflow phase status.

Four direct active tools remain blocked. There is no verified egress isolation backend in this release. User namespace/network creation failed in this cloud, and no Windows filtering/privileged isolation mechanism was assumed. Source/rate/exclusion flags and an optional proxy do not prevent direct bypass or enforce HTTPS path exclusions. Nuclei selection enables only the two reviewed native `.git/HEAD`/`.env` GET checks, not upstream templates. Selecting dnsx alone performs scoped native A/AAAA/CNAME enrichment without target HTTP. CNAME references, imported parent hosts, passive discoveries, archived URLs and AS relationships are rechecked against current authorization and never transfer it. Provider subprocesses use reviewed provider allowlists and rate/time/output flags; their provider network counts are not measured or represented as target reservations.

`enrichment/providers.py` is a separate application-owned metadata client. Only the fixed HTTPS Internet Archive CDX and RIPE Stat network-info/as-overview endpoints are permitted. All provider DNS addresses must be public unicast and are pinned to each connection; DNS caching, environment proxies, cookies and redirects are disabled. Persistent request reservations, rate/Retry-After waits, bounded retries/time/decompression, caps and expiring per-run metadata caches apply independently of target HTTP. Offline/demo/loopback lab never contacts providers. Cached metadata is restricted local data, excluded from routine exports. Cache reuse respects both the stored expiry and current configured TTL. Actual provider service collection remains unverified; local schema/pagination/failure/cancellation/destination tests are the verification evidence.

Technology signatures analyze captured headers, cookie names (never values), HTML metadata/scripts and JS markers. Each fingerprint records supporting locations/signatures, confidence and content hash. Advertised/weak markers do not establish a software version; versions remain unknown. Multiple locations may raise fingerprint confidence without establishing a vulnerability. Numeric/UUID route-family and parameter multiplicity grouping retains exact URL case, encoding, explicit ports, values, fragments and known methods. It does not delete evidence or suppress different request values. Priority version 1 records configurable component weights, reasons and confidence. Unobserved routes cannot exceed 35, and out-of-scope references score zero. Names alone do not imply a vulnerability or reachability.

`schema_v2.py` adds tool executions, provider cache, historical URLs, infrastructure, technologies, groups/members, endpoint priority and lineage without modifying the original tables. V1 config digests remain compatible when all V2 settings are absent/default. V1 reports/comparisons remain readable; an explicitly requested mutable report/resume adds new tables transactionally. Rerun reads a stopped, unlocked, checkpointed parent in SQLite immutable mode so even WAL/SHM sidecars are not created. Artifacts are independently copied after path, size and SHA-256 validation; there are no hard links. New jobs/counters and fresh candidate findings do not inherit completed queues or analyst confirmation. Parent analyst actions remain unchanged and are referenced in lineage. Fresh active reruns revalidate current scope before DNS and before every request; previous artifacts confer no authorization. Local-only reruns make zero target/provider requests and preserve prior HTTP collection timestamps. Final lineage records tools/versions, stage states, new/reused hashes, HTTP/provider counters and changed finding fingerprints.

The private-directory trust model excludes concurrent malicious modifications by another process with the same OS account. Artifact/report disk budgeting reserves approximate finalization space, not a hard filesystem quota. Real native Windows process/ACL/console behavior, Python 3.13, live provider service schemas/availability and graphical-browser behavior still require their own execution evidence.
